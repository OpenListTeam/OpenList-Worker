# 189Cloud 稳定性重构设计

**日期：** 2026-09-08

## 目标

让 Cloudflare Workers 上的 189Cloud 驱动接近 123pan 驱动的稳定性：复用已保存会话、避免并发登录、区分认证失败与网络故障，并按需获取目录分页。

## 设计

### 认证

初始化时对已有 Cookie 做一次轻量会话校验。校验成功则复用 Cookie；校验失败才执行完整 OAuth 登录。所有并发初始化请求通过单一 Promise 合并，避免同时执行多条登录流程。只有明确的 `InvalidSessionKey` 或 1010 响应才触发重新登录；522、5xx、超时和网络错误不触发登录。

### 请求

189 API 请求统一经过客户端请求层。GET 读请求使用有限次数、短退避重试；POST 写请求不自动重放。请求超时覆盖响应头和响应体读取，并在错误中保留接口路径和 HTTP 状态。OAuth 请求也使用同一超时保护。

### 列表

扩展存储列表调用以支持可选 `page` 与 `perPage`。189 驱动在有分页参数时只请求目标页；没有分页参数时使用最多 3 个并发请求加载剩余页面。路径解析仍使用按名称查找并命中即停。保留 Cloudflare 单次调用的子请求预算。

### 兼容性

其他驱动无需修改即可继续使用旧的 `list` 签名。分页参数为可选参数，默认行为保持兼容。缓存不在本次重构中引入外部 KV，避免新增部署依赖。

## 验证

- 189 单元测试覆盖会话校验、并发登录合并、522/超时分类、POST 不重试、分页请求和路径查找提前结束。
- 运行 `pnpm run test:189` 的等价本地命令。
