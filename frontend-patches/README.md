# 前端补丁维护

`upstream.json` 锁定官方前端版本和应用顺序。每份补丁表示该顺序下的一次功能变更，
需要更新时先按清单应用到干净源码，再修改所属功能并重新生成补丁。
共享文件可能由后续补丁继续修改，不能把单份补丁的反向检查当作整组已应用的证明；
构建脚本会在临时源码副本中按逆序验证整组补丁。

用量统计首次加载仍自动计算全部挂载，并在五分钟内复用缓存。上传完成事件合并后，
只重算上传目录匹配的最具体挂载，其他挂载的已有结果保留；“刷新用量”强制重算全部挂载。
若上传发生在初次统计期间，先完成初次统计，再刷新对应挂载，避免遗漏其他挂载。

本次整理已验证：除用量统计的预期修改，应用新旧补丁得到的源码逐文件一致。
视频恢复已合并为一份最终补丁，不再依赖追加补丁删除之前加入的恢复触发器。

初始化设置、登录状态和文件信息读取限定 30 秒，并在恢复前台或网络时检查实际
经过时间；超时取消挂起请求并显示错误，初始化错误提供原地刷新按钮。
上传、下载和修改文件的请求策略保持原样。普通视频中断后的条件恢复与浏览器
回归说明见 `docs/video-recovery.md`。

文件操作弹窗通过 `DriveDialogScope` 共用 Dropbox 风格，并把主题传入页面外层的弹窗。
目录选择器的嵌套弹窗也继承该作用域；管理页面使用同一组件时保留原来的样式。

文件图标统一由 `utils/icon.ts` 选择本地多色 SVG，列表、网格、搜索、压缩包内容和
文件信息页共用。颜色与图形同时区分类型，文件名继续使用原来的文字颜色；
图片和视频已有缩略图时仍显示缩略图，缺失或加载失败时使用对应图标。
目录优先于扩展名；扩展名不区分大小写，无法识别时回退后端类型，仍未知时显示通用图标。
`.ts` 在后端标为视频时按 MPEG transport stream 显示，否则按代码文件显示。

PDF 预览改用固定版本的 PDF.js 完整查看器，构建时由 `scripts/fetch-pdf-viewer.mjs`
下载官方 legacy release 并校验 SHA-256，部署到带版本和集成修订号的本地静态目录。
`pdf-viewer-bridge.mjs` 在初始化前开启 Range，关闭流式整文件下载和自动补取；
源站不支持 Range 时由 PDF.js 回退普通下载。跨域直链仍需要允许 CORS 并暴露
`Accept-Ranges`、`Content-Length`、`Content-Range`。搜索、打印、下载等操作可能继续读取更多数据。
修改查看器或桥接脚本时递增目录中的 `openlist` 修订号，同时更新前端补丁的入口路径。

打印入口通过 `pdf-print-preparation.mjs` 先选择全部、当前页或指定范围（如 `1-5,8`），
校验后只初始化所选页，再交给 PDF.js 原有打印流程渲染；预览仍保持懒加载。
范围按原文档页码输入、去重并按文档顺序打印；浏览器打印窗口中的页码对应这份
所选页面组成的打印任务，保持“全部”即可。选择或取消范围不会发起打印数据读取。
准备阶段显示所选页数进度，支持取消和失败重试，复用已加载页面，并在关闭/切换
文档时停止推进。取消后已发出的少量读取可能完成并缓存。
PDF.js 打印渲染阶段的读取失败也显示重试提示；失败后重试重新加载查看器并通过原握手
打开当前文档，避免复用 PDF.js 缓存的失败状态或等待未完成的读取清理。
一次性自动打印标志和所选页码随握手消费，重试保持原范围；文件签名不会放进
iframe 地址或持久保存。
正常再次打印和取消后继续仍复用已读取的数据。

`patchPdfPrintRange()` 在固定版本查看器中同步调整就绪检查、页面尺寸和渲染页码，
确保未选择的页不会进入打印队列；保留原有批注、自动旋转、进度、取消和打印服务。
补丁预期代码不唯一或变化时构建失败。共享字体、图片、页面树等仍可能读取额外范围；
不支持 Range 的源站或纯 XFA 文档可能需要更多乃至整本数据，不能按页数直接推算流量。
真实浏览器回归同时验证所选原页码、未选页内容未请求、缓存复用、横竖页旋转、
范围校验、当前页、取消、准备失败和真实 Range 503 后的范围保留重试。

PDF.js worker 的小范围构建期修正由 `patchPdfPageTree()` 管理：初始化校验嵌套
目录的最后一页时，将原本必需的页字典读取并发发出，保持原来的校验和数据范围。
首次/任意页的嵌套目录读取仍按需执行；原始发行包先校验摘要，预期代码不匹配则
构建失败。`pdf-page-tree.test.mjs` 直接执行部署 worker 的实际方法，覆盖并发、
按需读取、缓存复用、错误计数、循环引用和未消费的拒绝。
客户端模块的 `patchPdfRangeFetch()` 为实际带 Range 的 PDF `fetch` 设置
`cache: "no-store"`，避免 Chromium 的 HTTP 缓存将同 URL 分段请求重新排队；
初始请求、整文件回退和 PDF.js 内部数据缓存保持原策略，签名和取消原样传递。
预期 helper 不唯一或变化时构建失败；`pdf-range-fetch.test.mjs` 测试最终部署方法。
`pdf-browser-cache.test.mjs` 在 HTTP 缓存开启且没有请求拦截的真实 Chromium 中
验证分段并发、刷新、跳页和内部缓存复用，由 Build Verify 执行。
B2 的 PDF Range 与视频一样绕过 `fetch` 的回源缓存；普通下载和其他文件维持原有策略。
性能对比与适用范围见 `docs/pdf-preview-loading.md`。

首页左侧“分享”打开 `/@links`，保持文件浏览器的 Dropbox 风格；原后台分享页面保留。
分享数据复用 `/api/share/*` 接口，新建、编辑、启停和删除均在首页内完成。
沿用 Worker 管理权限：入口仅管理员可见；普通用户直接访问只显示权限提示，不请求分享列表。
搜索和状态筛选在本地完成，复制链接保留部署子路径，不依赖分享摘要模板。

焦点样式通过 `focus-styles.patch` 统一调整：菜单、按钮、分享筛选与搜索、文件操作弹窗、
上传面板、行内重命名和通用表单控件不再显示点击后的蓝色外框或阴影。
正常边线、当前选中项和校验错误样式保留，键盘焦点使用文字下划线提示。

分享编辑表单同一行的字段顶部对齐并统一控件高度，操作列标题与按钮左侧对齐。
更多菜单沿用文件菜单的图标、紧凑行距、浅灰悬停、删除分隔线和深色主题。

最近使用打开 `/@recent`，仅登录用户可见；成功打开普通文件后记录，访客和公开分享不记录。
后端使用当前存储驱动的独立 KV 键，以账号及用户根目录隔离，避免改写站点配置。
每个文件独立保存；列表保留最近 100 项及 90 天内记录，按服务端打开时间排序。
列表切回前台、其他标签页打开文件和每分钟自动刷新，实现同账号跨设备同步。
移除和清空只操作使用记录，文件保留在原位置。

首页移动端导航使用左侧滑入的 Hope UI Drawer，复用桌面侧栏的菜单和权限判断，
保留所有文件、最近使用、分享与刷新入口。抽屉支持遮罩、Esc、关闭按钮和菜单点击
收起，切回桌面宽度时关闭并释放滚动锁；组件卸载时清理断点监听。
抽屉在 Portal 中独立继承亮暗主题，适配窄屏、动态视口和安全区域，
并尊重系统减少动画设置。桌面侧栏和移动端新建菜单保持原有布局。

PC 端页头的菜单按钮可收起和展开侧栏，收起后主区域占据全部可用宽度。
所有文件、最近使用和分享页面共用布局状态，目录跳转保留当前状态；重新加载页面默认展开。
按钮支持键盘操作，提供中英文提示、展开状态和受控侧栏关联。
761px 及以上显示桌面按钮，移动端继续使用现有抽屉；隐藏侧栏保留组件实例，避免重新加载用量统计。

布局入口采用四宫格图标和深色带箭头提示，点击仍可切换列表、网格、大型网格和图片视图。
桌面搜索栏随页头剩余空间延伸到账号区域前，侧栏收起后继续扩宽；移动端沿用紧凑搜索布局。

首页搜索改为顶部直接输入并在主区域展示结果，不再打开搜索弹窗。输入防抖 300ms，
Enter 立即提交；Ctrl/Cmd+K 聚焦，Esc、清空和返回目录恢复原文件列表。
沿用当前目录、密码、类型范围和每页 100 条的搜索协议，保留登录失效跳转；
支持结果高亮、文件新标签预览、目录跳转、分页和失败重试。目录与账号改变、清空、
输入变化和组件卸载时取消请求，使用请求代次避免旧响应覆盖当前结果。
用户根目录按字面路径边界移除，避免正则特殊字符造成错误路径。
原目录内容保持挂载，清空搜索无需重新加载目录。手机布局隐藏单独的位置列，
将位置放在文件名下方；桌面结果显示名称、位置和大小，后端未提供的时间不展示。
浏览器回归覆盖无弹窗、筛选、分页、慢响应、清空、快捷键、根目录映射及移动端。

### Dropbox 风格首页

`dropbox-home.patch` 在现有搜索与侧栏补丁后应用，统一浅灰侧栏、白色内容区、
蓝色上传主按钮、紧凑文件列表与网格卡片。列表上方显示当前目录的服务端总项数，
进入选择状态时让位于批量操作。手机首页保留带文字的上传、新建文件夹与刷新入口，
隐藏重复的新建菜单，让顶部搜索占用更多空间；长文件夹名称允许换行。
保留原有权限判断、文件操作、搜索、侧栏折叠与抽屉，并适配深色模式。
样式局限于文件浏览器，登录与后台不受影响。

### Dropbox 风格登录页

`dropbox-login.patch` 将登录页改为蓝色品牌区与白色表单双栏布局，窄屏显示单列表单。
CSS 文件限定在登录页内，提供深色模式、可关联标签、自动填充和键盘提交。
保留密码散列登录、LDAP、OTP、记住账号、访客、SSO 回调及通行密钥流程；
SSO 与通行密钥入口改为带文字、可键盘操作的按钮。验证码阶段继续显示验证码标签。
浏览器回归覆盖密码与验证码请求、登录重定向、LDAP、错误提示、清除、
访客入口、通行密钥切换、第三方入口、暗色与 320–1440px 的布局。
